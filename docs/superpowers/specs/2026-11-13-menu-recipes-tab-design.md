# Вкладка «В меню» на странице Рецепты

## Зачем
Хозяйка готовит раз в несколько дней на пару дней вперёд. Перед готовкой ей нужно сразу видеть весь фронт работ:
все рецепты, которые нужны к этим дням, уже развёрнутые и пересчитанные, и что у них общего, чтобы объединить
операции (например, сварить яйца сразу на все рецепты).

## Цели
1. На странице «Рецепты» две вкладки: **«В меню»** (открыта по умолчанию) и **«Все рецепты»** (нынешний список).
2. **«Готовлю до…»**: ряд из 7 дней начиная с завтра (не зависит от недели, открытой в «Меню»); выбирается последний день готовки.
   По умолчанию — 4 дня, начиная с завтра.
3. В списке только рецепты, которые нужны с завтра по выбранный день и ещё **не покрыты остатками**, по порядку
   первого приёма пищи, где они нужны. Каждый развёрнут: «нужно к: пт обед, сб ужин», счётчики порций с
   «Приготовлено» (как на странице рецепта, но только по этим дням), ингредиенты и шаги, пересчитанные на эти порции.
4. Вверху сводка **«Общее для нескольких рецептов»**: продукты, которые встречаются в 2+ рецептах списка, с суммой
   и разбивкой: «Яйца — 5 шт: Кекс 2, Салат 3». Следует за счётчиками: поменяли порции — поменялась сводка.
5. После «Приготовлено» рецепт уходит из списка в свёрнутую строку «Уже приготовлено к этим дням: Суп, Кекс»
   (ссылки на рецепты).

## Не цели
- Распознавать одинаковые операции в тексте шагов (ненадёжно) — объединяем по продуктам.
- Менять меню из этой вкладки.
- Новые данные или синхронизация: всё считается из меню и остатков.

## Подходы
- **«Готовлю до…»** — выбрано: одно нажатие задаёт ровно эту готовку, остатки сами убирают приготовленное.
- Вся неделя по дням без выбора — отвергнуто: сводка общих продуктов считалась бы на неделю, а не на эту готовку.
- Галочки у каждого дня — отвергнуто: больше нажатий, пропуск дня при готовке на пару дней вперёд почти не нужен.

## Как устроено
- Вкладка — в адресе (`/recipes` — «В меню», `/recipes?tab=all` — «Все рецепты»), чтобы «назад» со страницы
  рецепта возвращал на ту же вкладку.
- Список считает чистая функция (новый `src/lib/cooking.ts`, с тестами) из потребностей и покрытия остатков
  (`useLeftoversStore`): рецепт входит, если у него есть потребность в датах [завтра, выбранный день], не закрытая
  «Съедено» и с недостающими граммами. Порядок — по первой такой потребности (дата, затем завтрак → перекус).
- Рецепты **без «Веса готового блюда»** в остатках не участвуют, поэтому берутся прямо из выбранных вариантов меню
  в этих днях; показываются весь рецепт (множитель «Рецептов», как сейчас) с пометкой, что записать нельзя, и из
  списка сами не уходят.
- `CookPanel` получает необязательные `from` и `until`: счётчики по умолчанию берут потребности только в этих днях.
  Без них — как сейчас (весь открытый период).
- Сводка: ингредиенты рецептов (`recipe.ingredients`) × множитель каждого рецепта из его `CookPanel`; продукты
  сравниваются по названию без регистра; суммируются при одной единице, при разных — через «+» («200 г + 1 шт»);
  «по вкусу» без количества — только список рецептов. Округление — как в пересчёте рецепта.

## Решения (согласованы)
- По умолчанию 4 дня с завтра; сегодняшний день во вкладку не входит; выбор дня не запоминается между заходами.
- Карточку рецепта можно свернуть нажатием на заголовок; по умолчанию развёрнута.
- Если к выбранным дням готовить нечего — «К этим дням всё приготовлено» (или «В меню на эти дни нет рецептов»)
  и ссылка на «Все рецепты».
