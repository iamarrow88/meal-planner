# Munch Mood

Веб-приложение (PWA) для составления меню на день или неделю. Рецепты и сеты ведутся в Obsidian и загружаются в приложение папкой.

Стек: Vue 3 + TypeScript, vue-router, Pinia, Tailwind CSS 4, Dexie (IndexedDB), Supabase для синхронизации.

```
src/
  lib/          разбор заметок, импорт папки, база, даты, список покупок — без привязки к Vue
  stores/       Pinia: recipes, sets, favorites, plan (период и дни меню), pantry (продукты дома), sync
  views/        страницы (маршруты в router.ts)
  components/   PeriodBar, MealSlot, GroupPicker, ProductPicker, ImportCard, SyncCard
  style.css     Tailwind, цвета темы и общие классы (card, btn-*, chip…)
```

```bash
npm install
npm run dev      # разработка
npm run build    # сборка в dist/
```

## Импорт из Obsidian

Вкладка **Данные → Выбрать папку**. Назначение файла определяется по папке в его пути:

| Папка | Что это |
|---|---|
| `Рецепты` | рецепты |
| `Завтраки`, `Обеды`, `Ужины`, `Перекусы` | сеты этого приёма пищи |
| остальные (например, `Мои меню по дням`) | пропускаются |

Повторный импорт обновляет данные по имени файла, а рецепты и сеты, файлов которых больше нет, удаляет. Редактировать сеты и рецепты нужно в Obsidian. Пример папки — в `examples/menu`.

### Сет

Каждый раздел `##` — это группа блюд. Разделы «Оценка», «КЖБУ» и «Как готовить» не читаются.

```markdown
## Каша на молоке 2,5% 180 мл + вода (один вариант на выбор):
- геркулес (40 гр в сухом виде)
- гречка отварная (40 гр в сухом виде или 140 гр в готовом)

## Добавка (один вариант на выбор или по половине от двух указанных):
- мёд (30 гр)
- банан (90 гр)

## Чай/кофе + молоко 2,5% (50 мл)

## Десерт (один вариант на выбор):
- [[Шоколадные маффины (~40 минут)]] (50 гр)
```

- Несколько вариантов — выбирается один; «два варианта» — два; «по половине» — один или два, при двух вес и количество в покупках делятся пополам.
- Раздел без списка или с одним вариантом входит в сет всегда.
- Если указано два веса, в покупки идёт первый.
- `индейка тушеная (170 гр) или отварная (130 гр)` и `рыба: окунь (170 гр), лосось (100 гр)` становятся отдельными вариантами.
- Продукты одного блюда перечисляются через ` + `, а не через запятую: `Шаурма: лаваш (70 гр) + овощи (150 гр) + соус (сметана 10% 20 гр + кетчуп 10 гр)`. В покупки идут лаваш, овощи, сметана и кетчуп.

### Рецепт

```markdown
---
tags:
  - Завтрак
---
Вес готового блюда: 350 гр
## Ингредиенты
- Банан — 120 гр
- Яйца (C1) — 2 шт (100 гр)
- Ванилин

## Как готовить
...
```

Название и время берутся из имени файла: `Шоколадные маффины (~40 минут).md`. Сет ссылается на рецепт через `[[...]]`. В покупки идёт доля рецепта: порция 50 гр от блюда весом 350 гр — это 1/7 ингредиентов, «вся порция» — весь рецепт, «половина порции» или «1/2 порции» — половина; так же работают «1/4 порции», «¼ порции» и «0,5 порции». Если веса готового блюда нет, считается весь рецепт, и приложение об этом предупреждает.

### Подбор по продуктам

На карточке дня **🧺 Подобрать по продуктам** открывает поиск по продуктам из рецептов и сетов. Под каждым приёмом пищи
появляются до трёх сетов, где этих продуктов больше всего, и под каждым — что ещё понадобится (по порядку сета
и рецептов, без специй); нажатие выбирает сет и в каждом разделе — вариант с этими
продуктами (прямо указанный в сете важнее спрятанного в рецепте). Разделы, где подходящего варианта нет, подсвечиваются.
Выбранные продукты хранятся только на этом устройстве, отдельно для каждого дня.

### Сохранённые меню

На вкладке меню **💾 Сохранить меню** запоминает всю открытую неделю или один её день под названием
(меню с тем же названием заменяется). В **📋 Мои меню** меню подставляется с выбранного дня открытой недели:
недельное, начатое со среды, займёт среду — вторник следующей недели; дневное — только выбранный день; дальше блюда правятся как обычно, сохранённое меню от этого не меняется.
Если на эти даты уже что-то выбрано, приложение спросит, заменить ли. Сеты, которых больше нет в Obsidian, пропускаются.
Меню синхронизируются между устройствами; если база Supabase создана раньше, выполните
[supabase/schema.sql](supabase/schema.sql) ещё раз — он добавит новый вид данных, не трогая остальное.

### Список покупок

- Продукты складываются без учёта регистра, «ё», окончаний, скобок и жирности: «Молоко», «молоко 2,5%» и «Молоко 1,5%» — одна строка «Молоко (1,5%/2,5%)», «Яйцо» и «Яйца» — тоже одна. Пометки «в собственном соку», «замороженный», «консервированный» и т.п. делают продукт отдельным.
- Единицы пересчитываются (`src/lib/units.ts`): кг → г, л → мл, 1 ст. л. = 15 мл = 3 ч. л., 1 стакан = 250 мл. Если продукт везде в одной единице, она остаётся; если в разных — сумма в г или мл (от 1000 — в кг или л), смешанные ложки — в ч. л.
- Граммы, штуки и ложки одного продукта сводятся по примерному весу из таблицы `WEIGHTS` в `src/lib/units.ts`: 1 яйцо ≈ 50 г, 1 картофелина ≈ 150 г, 1 ч. л. мёда ≈ 10 г и т.п. Сумма показывается в граммах, а для яиц, хлебцев и чеснока — в штуках или зубчиках, для жидкостей — в мл. Продукты, которых нет в таблице, остаются отдельными строками; чтобы добавить продукт, достаточно дописать его туда.
- Соль, перец, специи, зелень, разрыхлитель, ванилин, приправы и всё, что помечено «(специи)», идут одной строкой «Специи и приправы» без количества.
- Вода, бульон и отварные крупы в список не попадают.

- Список можно сортировать по алфавиту или по отделам магазина (овощи, молочка, бакалея…). Отдел определяется по словам в названии продукта; что не узнано — в «Другое».

Списки специй и исключений — в `src/lib/shopping.ts`, правила отделов — в `src/lib/categories.ts`.

## Публикация (GitHub Pages)

Каждый пуш в ветку `dev` собирает сайт и публикует его на GitHub Pages
([.github/workflows/deploy.yml](.github/workflows/deploy.yml)). Настройка один раз:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. **Settings → Environments → github-pages → Deployment branches and tags:** добавить `dev`
   (по умолчанию публиковать можно только из основной ветки).
3. **Settings → Secrets and variables → Actions → New repository secret:** `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY` — те же значения, что в `.env.local`.
4. В Supabase: **Authentication → URL Configuration → Site URL** — адрес сайта, чтобы ссылка из письма
   о подтверждении почты вела на сайт, а не на localhost.

Ход сборки — на вкладке **Actions**; там же **Run workflow** пересобирает сайт без нового пуша.

## Синхронизация между устройствами (Supabase)

Данные всегда хранятся на устройстве (приложение работает и без сети), а при входе в аккаунт
изменения отправляются в Supabase и скачиваются на другие устройства. При конфликте побеждает
более позднее изменение. Папку достаточно загрузить на компьютере: на телефон данные придут через синхронизацию.

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (бесплатный тариф подходит).
2. Откройте **SQL Editor → New query**, вставьте содержимое [supabase/schema.sql](supabase/schema.sql) и нажмите **Run**.
3. В **Project Settings → API** скопируйте *Project URL* (вида `https://xxxx.supabase.co`, без `/rest/v1/`) и ключ *anon public*.
4. Скопируйте `.env.example` в `.env.local` и вставьте туда эти значения. Перезапустите `npm run dev`.
5. В приложении: вкладка **Данные → Зарегистрироваться**, подтвердите почту по ссылке из письма и войдите.
   На остальных устройствах войдите с той же почтой и паролем.

Если подтверждение почты не нужно, его можно отключить: **Authentication → Sign In / Providers → Email → Confirm email**. *heart*
