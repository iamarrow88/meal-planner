# Munch Mood

Веб-приложение (PWA) для составления меню на день или неделю. Рецепты и сеты ведутся в Obsidian и загружаются в приложение папкой.

Стек: Vue 3 + TypeScript, vue-router, Pinia, Tailwind CSS 4, Dexie (IndexedDB), Supabase для синхронизации.

```
src/
  lib/          разбор заметок, импорт папки, база, даты, список покупок — без привязки к Vue
  stores/       Pinia: recipes, sets, favorites, plan (период и дни меню), pantry (продукты дома), sync
  views/        страницы (маршруты в router.ts), Главная — HomeView
  components/   PeriodBar, MealSlot, GroupPicker, ProductPicker, SavedMenus, ImportCard, SyncCard
  style.css     Tailwind, цвета темы и общие классы (card, btn-*, chip…)
```

```bash
npm install
npm run dev      # разработка
npm run build    # сборка в dist/
```

## Импорт из Obsidian

Вкладка **Данные → Выбрать папку**. Назначение файла определяется по папке в его пути:

| Папка | Что это |
|---|---|
| `Рецепты` | рецепты |
| `Завтраки`, `Обеды`, `Ужины`, `Перекусы` | сеты этого приёма пищи |
| остальные (например, `Мои меню по дням`) | пропускаются |

Повторный импорт обновляет данные по имени файла, а рецепты и сеты, файлов которых больше нет, удаляет. Редактировать сеты и рецепты нужно в Obsidian. Пример папки — в `examples/menu`.

### Сет

Каждый раздел `##` — это группа блюд. Разделы «Оценка», «КЖБУ» и «Как готовить» не читаются.

```markdown
## Каша на молоке 2,5% 180 мл + вода (один вариант на выбор):
- геркулес (40 гр в сухом виде)
- гречка отварная (40 гр в сухом виде или 140 гр в готовом)

## Добавка (один вариант на выбор или по половине от двух указанных):
- мёд (30 гр)
- банан (90 гр)

## Чай/кофе + молоко 2,5% (50 мл)

## Десерт (один вариант на выбор):
- [[Шоколадные маффины (~40 минут)]] (50 гр)
```

- Несколько вариантов — выбирается один; «два варианта» — два; «по половине» — один или два, при двух вес и количество в покупках делятся пополам.
- Раздел без списка или с одним вариантом входит в сет всегда.
- Если указано два веса, в покупки идёт первый.
- `индейка тушеная (170 гр) или отварная (130 гр)` и `рыба: окунь (170 гр), лосось (100 гр)` становятся отдельными вариантами.
- Продукты одного блюда перечисляются через ` + `, а не через запятую: `Шаурма: лаваш (70 гр) + овощи (150 гр) + соус (сметана 10% 20 гр + кетчуп 10 гр)`. В покупки идут лаваш, овощи, сметана и кетчуп.

### Рецепт

```markdown
---
tags:
  - Завтрак
---
Вес готового блюда: 350 гр
## Ингредиенты
- Банан — 120 гр
- Яйца (C1) — 2 шт (100 гр)
- Ванилин

## Как готовить
...
```

Название и время берутся из имени файла: `Шоколадные маффины (~40 минут).md`. Сет ссылается на рецепт через `[[...]]`. В покупки идёт доля рецепта: порция 50 гр от блюда весом 350 гр — это 1/7 ингредиентов, «вся порция» — весь рецепт, «половина порции» или «1/2 порции» — половина; так же работают «1/4 порции», «¼ порции» и «0,5 порции». Если веса готового блюда нет, считается весь рецепт, и приложение об этом предупреждает.

### Готовка и остатки приготовленного

На странице рецепта в блоке **Сколько готовить** — счётчик у каждого размера порции из сетов, где есть рецепт
(«В1 Каша с добавкой — 50 г»; «половина порции» — половина веса готового блюда), и строка «своя» в граммах.
Счётчики сами заполняются из меню открытого периода (от сегодня): сколько порций этого блюда стоит в меню и ещё не
покрыто остатками, с датами. Если блюда в меню нет — стоит весь рецепт в порциях первого сета. Числа можно править;
раздел «Ингредиенты» пересчитывается на итог в граммах: г и мл — до целых, штуки и ложки — до половинок, «щепотка» и
«по вкусу» не меняются. Без «Веса готового блюда» счётчик просто умножает рецепт.

**Приготовлено** записывает партию: рецепт, сегодняшняя дата, граммы. Дальше:

- **Главная → 🍲 Уже приготовлено:** сколько осталось, сколько из этого уже стоит в меню, сколько свободных порций
  каждого сета и когда приготовлено; старше 3 дней — подсвечивается. «Списать» — если выбросили, «Взвесила» — указать,
  сколько лежит на самом деле.
- **Меню:** блюдо из остатков в выбранном сете берётся из них само: «🍲 Из приготовленного» (или «не хватает N г»).
  Остатки занимаются по порядку дат, старшие партии первыми; партия не покрывает дни до своего приготовления.
  **Съедено** списывает граммы (по умолчанию — взятое из остатков) и закрывает этот приём пищи; отметку можно снять.
  Прошедший день без отметки продолжает занимать граммы и напоминает «Отметить съеденным?». **Готовлю заново** —
  не брать из уже записанных партий (новая партия этот приём пищи покроет). Под невыбранным приёмом пищи —
  «Уже приготовлено»: сеты с блюдами, остатки которых свободны.
- **Персоны:** «На сколько человек готовить обычно» — в меню и в списке покупок, это одно число; у любого приёма пищи
  в меню можно поставить своё.
- **Список покупок:** что покрыто остатками, не покупается (продукты сверх рецепта у варианта — покупаются).

Остатки и число персон синхронизируются между устройствами. Расчёт — в `src/lib/portions.ts` и
`src/lib/leftovers.ts`, тесты — `npm test`.

### Рецепты в меню

Вкладка **Рецепты → В меню** (открывается по умолчанию) — для готовки на несколько дней вперёд. **Готовлю до:** —
последний день готовки (по умолчанию 4 дня, начиная с завтра). Показываются рецепты меню на эти дни, которые ещё не
приготовлены, по порядку: когда нужны, счётчики порций (только по этим дням) с кнопкой «Приготовлено», ингредиенты
и шаги, пересчитанные на эти порции; карточку можно свернуть. Сверху — **Общее для нескольких рецептов**: продукты
из двух и больше рецептов с суммой и разбивкой («Яйца — 5 шт: Кекс 2 шт, Салат 3 шт»), без соли, воды и специй.
Приготовленное уходит в строку «Уже приготовлено к этим дням». Обычный список — на вкладке «Все рецепты».

### Подбор по продуктам

На главной в разделе **🧺 Продукты дома** выбирается, что есть дома (поиск по продуктам из рецептов и сетов).
Список один на все дни и сохраняется — когда продукты меняются, его просто правят там же. В меню на каждом дне
под каждым ещё не выбранным приёмом пищи появляются до трёх сетов, где этих продуктов больше всего, и под каждым — что ещё понадобится (по порядку сета
и рецептов, без специй); нажатие выбирает сет и в каждом разделе — вариант с этими
продуктами (прямо указанный в сете важнее спрятанного в рецепте). Разделы, где подходящего варианта нет, подсвечиваются.
Под выбранным сетом видно, что ещё нужно докупить именно для выбранных в нём вариантов; если поменять вариант, список обновится.
Каждый день недели начинает предложения с других сетов, чтобы неделя не состояла из одних и тех же;
**Другие** листает дальше. Список продуктов синхронизируется между устройствами.

### Добавить в меню

Сет можно поставить в меню, не открывая вкладку меню: кнопка **Добавить в меню** на странице сета и **＋ В меню**
в списке сетов и в избранном на главной. Выбираются день (дата или «Сегодня»/«Завтра») и приём пищи — по умолчанию
тот, для которого сет, но можно любой. Если на этот день и приём уже что-то выбрано, приложение предупредит, что заменит.
На странице сета вместе с ним сохраняются выбранные варианты.

### Оценки

На странице сета и рецепта можно поставить от 1 до 5 звёзд (та же звезда ещё раз снимает оценку); в списках оценка
видна под названием. Оценки синхронизируются и переживают повторный импорт папки. Как они используются:

- **Подбор по продуктам:** при одинаковом числе совпавших продуктов выше сеты с более высокой оценкой
  (без оценки — как 3 звезды); в разделах сета автоматически выбирается вариант с рецептом, оценённым выше.
- **Предложение дня:** рецепты с 1–2 звёздами не предлагаются; «давно не ели» начинаются с любимых,
  «а вы пробовали» — с оценённых на 4–5, но ещё не бывших в меню.
- **Избранное на главной** сортируется по оценке.

### Главная

Вкладка **Главная** открывается первой:

- **Предложение дня** — рецепт из меню, который не готовили больше 14 дней («Вы давно не ели…»), или рецепт,
  которого ещё ни разу не было в меню («А вы пробовали…?»), со ссылками на рецепт и сеты, где он есть.
  Весь день показывается одно и то же предложение, **Другое предложение** листает дальше. Учитываются рецепты,
  выбранные в сетах меню; если рецепт уже стоит в меню на будущее, о нём не напоминается.
- **Избранное** — сеты со звёздочкой по приёмам пищи.
- **Сохранённые меню** — тот же список, что в меню: подставить на открытую неделю или удалить.

### Сохранённые меню

На вкладке меню **💾 Сохранить меню** запоминает всю открытую неделю или один её день под названием
(меню с тем же названием заменяется). На неделе у каждого дня с блюдами есть **💾 Сохранить день** — так любой
день недели сохраняется отдельным дневным меню. В **📋 Мои меню** меню подставляется с выбранного дня открытой недели:
недельное, начатое со среды, займёт среду — вторник следующей недели; дневное — только выбранный день; дальше блюда правятся как обычно, сохранённое меню от этого не меняется.
Если на эти даты уже что-то выбрано, приложение спросит, заменить ли. Сеты, которых больше нет в Obsidian, пропускаются.
Меню синхронизируются между устройствами.

### Список покупок

- Продукты складываются без учёта регистра, «ё», окончаний, скобок и жирности: «Молоко», «молоко 2,5%» и «Молоко 1,5%» — одна строка «Молоко (1,5%/2,5%)», «Яйцо» и «Яйца», «Хлебец» и «Хлебцы», «Огурец» и «Огурцы» — тоже одна, «Сыр обычный» — это просто «Сыр», «Помидоры-черри» — то же, что «Помидоры черри». Пометки «в собственном соку», «замороженный», «консервированный» и т.п. делают продукт отдельным; «в собственном соку» и «консервированный» при этом одно и то же: «Тунец в собственном соку» и «Тунец консервированный» — одна строка.
- Единицы пересчитываются (`src/lib/units.ts`): кг → г, л → мл, 1 ст. л. = 15 мл = 3 ч. л., 1 стакан = 250 мл. Если продукт везде в одной единице, она остаётся; если в разных — сумма в г или мл (от 1000 — в кг или л), смешанные ложки — в ч. л.
- Граммы, штуки и ложки одного продукта сводятся по примерному весу из таблицы `WEIGHTS` в `src/lib/units.ts`: 1 яйцо ≈ 50 г, 1 картофелина ≈ 150 г, 1 ч. л. мёда ≈ 10 г и т.п. Сумма показывается в граммах, а для яиц, хлебцев и чеснока — в штуках или зубчиках, для жидкостей — в мл. Продукты, которых нет в таблице, остаются отдельными строками; чтобы добавить продукт, достаточно дописать его туда.
- Соль, перец, специи и пряности (паприка, корица, кориандр…), зелень и травы (петрушка, укроп, кинза, базилик, зелёный лук…), сода, разрыхлитель, ванилин, приправы и всё, что помечено «(специи)», идут одной строкой «Специи и приправы» без количества. В подборе по продуктам их нет ни в поиске, ни в «ещё нужно».
- Вода, бульон, отварные крупы и чай/кофе к приёму пищи в список не попадают и в подборе по продуктам не показываются.

- Список можно сортировать по алфавиту или по отделам магазина (овощи, молочка, бакалея…). Отдел определяется по словам в названии продукта; что не узнано — в «Другое».
- Отмеченное купленным уходит в раздел «Куплено» в самом конце, чтобы некупленное шло подряд; отдел, где всё куплено, сверху пропадает.

Списки специй и исключений — в `src/lib/shopping.ts`, правила отделов — в `src/lib/categories.ts`.

## Публикация (GitHub Pages)

Каждый пуш в ветку `dev` собирает сайт и публикует его на GitHub Pages
([.github/workflows/deploy.yml](.github/workflows/deploy.yml)). Настройка один раз:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. **Settings → Environments → github-pages → Deployment branches and tags:** добавить `dev`
   (по умолчанию публиковать можно только из основной ветки).
3. **Settings → Secrets and variables → Actions → New repository secret:** `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY` — те же значения, что в `.env.local`.
4. В Supabase: **Authentication → URL Configuration → Site URL** — адрес сайта, чтобы ссылка из письма
   о подтверждении почты вела на сайт, а не на localhost.

Ход сборки — на вкладке **Actions**; там же **Run workflow** пересобирает сайт без нового пуша.

## Синхронизация между устройствами (Supabase)

Данные всегда хранятся на устройстве (приложение работает и без сети), а при входе в аккаунт
изменения отправляются в Supabase и скачиваются на другие устройства. При конфликте побеждает
более позднее изменение. Папку достаточно загрузить на компьютере: на телефон данные придут через синхронизацию.

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (бесплатный тариф подходит).
2. Откройте **SQL Editor → New query**, вставьте содержимое [supabase/schema.sql](supabase/schema.sql) и нажмите **Run**.
3. В **Project Settings → API** скопируйте *Project URL* (вида `https://xxxx.supabase.co`, без `/rest/v1/`) и ключ *anon public*.
4. Скопируйте `.env.example` в `.env.local` и вставьте туда эти значения. Перезапустите `npm run dev`.
5. В приложении: вкладка **Данные → Зарегистрироваться**, подтвердите почту по ссылке из письма и войдите.
   На остальных устройствах войдите с той же почтой и паролем.

Если база создана до появления сохранённых меню, оценок и продуктов дома, выполните
[supabase/schema.sql](supabase/schema.sql) ещё раз (данные он не трогает): старая база принимает только
прежние виды данных, и синхронизация показывает ошибку. После этого запуска новые разделы приложения
синхронизируются без повторов.

Если подтверждение почты не нужно, его можно отключить: **Authentication → Sign In / Providers → Email → Confirm email**. *heart*
